EXPERIMENT 1 – “One-shot tuning vs. exhaustive sweeps”
============================================
1. Goal
   Quantitatively show that a single C3PO run reaches or surpasses the best grid-searched baseline on reward/KL while reducing GPU cost by ≥5×.

2. Models
   • Pythia-1.4B (HF id: eleutherai/pythia-1.4b)
   • Mistral-7B-Instruct (HF id: mistralai/Mistral-7B-Instruct)

3. Datasets / Tasks
   • AlpacaFarm (instruction-following dialogue, v1.0)  
   • UltraFeedback (long-form dialogue, 2023-10 dump)  
   • Reddit TL;DR (summarisation, 2020 cleaned split)  
   • IMDb Positive Steering (sentiment re-writing, “IMDb-P” split)  
   • Anthropic Harmless (safety, v0.5)

4. Dataset preprocessing (common)
   a) Deduplicate by SHA-1 over the raw prompt text.
   b) Filter length 4–512 tokens (sentencepiece of base model).
   c) Pairwise preference construction exactly as in DPO: each record contains (chosen, rejected) responses + prompt; discard if reward-model margin |ΔR|<0.05 to avoid label noise.
   d) Tokenise with the model-specific tokenizer; truncate/pad to 512 tokens per string, pad to multiple of 8 for tensor cores.

5. Data split
   • 80 % train / 10 % validation / 10 % hold-out test.
   • Same random seed (2023) for all methods to guarantee identical splits.

6. Baselines & grids
   a) DPO: β ∈ {0.1,0.2,0.4,0.8,1.6,3.2,6.4,10} (8 runs)  
   b) DiscoPOP: β ∈ {0.05,0.1,0.2,0.5,1,2,3,5} (8 runs)  
   c) PPO: KL-target κ ∈ {0.5,1,2,5} (4 runs)  
   d) SA-DPO (single PID run, gains from original paper †).

7. Optimiser & schedule (all methods)
   • AdamW, lr=1 e-5, β₁=0.9, β₂=0.95, weight-decay 0.1  
   • cosine schedule w/ 200 warm-up steps  
   • batch size 128 preference pairs  
   • 3 epochs over train split  
   • gradient-accumulation 4 → effective batch 512  
   • fp16 w. bfloat16 accumulate (Ampere).

8. Seeds & repetition
   • Seeds {42, 1234, 2023} (3 independent runs).   
   • Report mean±95 %CI over seeds.   
   • For each run store checkpoints each 500 optimisation steps.   
   • Selection: “best-val” (highest validation reward) for final evaluation; also log last-epoch numbers to measure over-fit.

9. Evaluation metrics
   Primary:  
   • Normalised reward (scale-matched to original RMs, higher=better).  
   • Mean KL(π||π₀) on validation.  
   Secondary:  
   • ROUGE-L (TL;DR), sentiment accuracy (IMDb-P), MT-Bench overall (dialogue), Harmlessness rate (Anthropic safety classifier).  
   • Runtime metrics: GPU-hours, wall-clock seconds per 1 k steps, peak VRAM.  
   • Energy (J) via nvidia-smi –query-accounted.

10. Hyper-parameter analysis
    • For C3PO sweep η_dual ∈ {0.02, 0.05, 0.1} on AlpacaFarm only to confirm default choice, record its effect on convergence & KL.

11. Robustness
    • Add 5 % Gaussian noise to reward at training time; rerun best C3PO and best-grid DPO once, compare final reward drop.

12. Compute tracking
    • Log forward + backward FLOPs with ptflops; store JSON.  
    • Wall-clock per step from time.time().  
    • Memory from torch.cuda.max_memory_allocated().

13. Expected runtime budget
    • Per (task,model) C3PO: 8 h on single A100-80 GB.   
    • Baseline grids: 8–12 runs ⇒ 40–60 h on identical GPU.

14. Example code skeleton
    ```python
    from peft import prepare_model_for_kbit_training
    from transformers import AutoModelForCausalLM, AutoTokenizer
    from accelerate import Accelerator
    from c3po import C3POLoss
    accelerator = Accelerator(log_with="wandb")
    model = AutoModelForCausalLM.from_pretrained("mistralai/Mistral-7B-Instruct", torch_dtype=torch.bfloat16)
    tok = AutoTokenizer.from_pretrained(..., padding_side="left")
    model = prepare_model_for_kbit_training(model)
    loss_fn = C3POLoss()
    for step, batch in enumerate(train_loader):
        with accelerator.accumulate(model):
            out_chosen = model(**batch["chosen"])
            out_reject = model(**batch["reject"])
            loss, kl, beta = loss_fn(batch["feats"],
                                     out_chosen.logits, out_reject.logits,
                                     batch["ref_c"], batch["ref_r"])
            accelerator.backward(loss)
            opt.step(); sched.step(); opt.zero_grad()
    ```
    Complete, fully-runnable scripts are in ./scripts/exp1/*.

† PID gains (K_p=0.05, K_i=0, K_d=0.2) copied from SA-DPO repo; confirmed stable on AlpacaFarm.

EXPERIMENT 2 – “Context awareness & safety sensitivity”
------------------------------------------------
1. Goal
   Demonstrate that the learned per-sample β_i correlates with input risk/difficulty and that freezing it hurts safety.

2. Model & dataset
   • Model: Mistral-7B-Instruct  
   • Training set: Anthropic Harmless (≈160 k pairs)  
   • Extra evaluation sets (real, public):
       A. Benign – subset of Anthropic Helpful (1 k)
       B. Long & High-entropy – top 10 % length prompts within Harmless (1 k)
       C. Adversarial Jailbreak – AdvBench-Instruct v1.0 (1 k)
       D. Medical domain – MedQA-USMLE dev set (1 k Q-A pairs)

3. Pre-processing
   • Same tokenisation as Exp-1.  
   • For MedQA generation, convert (question, long answer) into instruction format to query the model, collect reference answer for reward model.

4. Training protocol
   • 2 epochs C3PO, identical optimiser/lr as Exp-1.  
   • Log β_i, KL_i, toxicity score (Perspective API), and reward per sample.

5. Metrics
   Primary:   
   • Median β_i per split.  
   • Harmlessness pass rate on Anthropic Harmless eval set.  
   Secondary:   
   • Reward, KL variance σ²_KL, correlation Spearman-ρ(β_i, feature).

6. Ablation study
   • After 1 epoch, store mean β̄.  
   • “Freeze” run: detach MLP outputs, replace with β̄ scalar for epoch-2.

7. Robustness stress
   • Remove 20 % of toxicity-flagged samples from train set and redo training → check if β_i on split-C still rises (should).

8. Evaluation code excerpt
   ```python
   # correlation analysis
   import scipy.stats as st
   rho_len, _ = st.spearmanr(beta_all, prompt_lengths)
   rho_tox, _ = st.spearmanr(beta_all, toxicity_scores)
   ```

9. Resource use
   • Full run <12 GPU-hours (single A100).

EXPERIMENT 3 – “Trust-region & stability stress test”
------------------------------------------------
1. Goal
   Verify monotone KL constraint satisfaction and robustness to reward scale shift.

2. Setting
   • Model: Pythia-1.4B  
   • Dataset: UltraFeedback (dialogue)  
   • 1 M optimisation steps; batch 256; log every 50 steps.

3. Reward perturbation
   • At global step 3 000 multiply rewards by 0.3 for exactly 500 steps; revert afterwards.

4. Compared methods
   i) C3PO (η=0.05)  
   ii) SA-DPO (PID)  
   iii) Fixed-β DPO (β tuned to 1.6 via grid, best reward pre-shift).

5. Logged series
   • KL_t – κ_max, β̄_t, reward_t  
   • Oscillation amplitude: rolling std over 1 000-step window.

6. Metrics & success criteria
   • Constraint violation rate (% steps with KL>κ_max) should be 0 for C3PO.  
   • Recovery steps: N s.t. reward_N ≥0.95·reward_pre.

7. Robustness extension
   • Add adversarial word-dropout (10 %) during shift; check if methods remain stable.

8. Expected compute
   • Each variant 6 h on a single A100 (mixed-precision, gradient-checkpointing).
